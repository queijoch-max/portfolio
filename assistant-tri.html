Assistant IA de tri SAV - Python, FastAPI et IA locale

Application web qui trie automatiquement les demandes clients d'un service après-vente grâce à une IA 100 % locale, puis propose un brouillon de réponse relu par un agent avant envoi.

IA locale Python FastAPI Pydantic SQLAlchemy Ollama

Le projet

Ce projet répond à un cas métier concret : « Cycles Mistral », réseau fictif de 6 ateliers de vélos électriques à Lyon, reçoit environ 250 messages par semaine. Deux personnes y passent 12 heures à les lire, les classer et les transférer, pendant que des urgences (batterie qui chauffe, freins) se perdent parmi les questions simples.

L'objectif : passer sous les 3 heures par semaine, sans jamais laisser une urgence non vue. La règle d'or : l'IA propose, l'humain décide. Aucune réponse ne part au client sans validation d'un agent. Le projet est en cours de développement.

Ce que j'ai développé

J'ai construit une API avec FastAPI et Python 3.13, des schémas de données Pydantic, une base SQLite gérée avec SQLAlchemy et Alembic, et un modèle d'IA local (Ollama, Qwen 2.5) : les données clients ne quittent jamais la machine.

Fonctionnalités principales

  • Formulaire client avec numéro de suivi, puis analyse en arrière-plan de chaque demande
  • Analyse IA : catégorie, urgence sur 4 niveaux, résumé, atelier concerné, justification et score de confiance
  • Garde-fous écrits en code : mots-clés de sécurité qui forcent l'urgence critique, masquage des numéros de carte avant l'appel à l'IA, protection contre l'injection de prompt
  • Brouillon de réponse construit par le code autour d'une phrase personnalisée écrite par l'IA, modifiable avant envoi
  • Robustesse : nouvelle tentative puis mode dégradé si l'IA échoue, aucune demande n'est perdue
  • Tableau de bord SAV trié par urgence (en cours de développement)

Mesurer la qualité de l'IA

J'ai constitué un jeu de 40 messages annotés à la main et des scripts d'évaluation pour mesurer les résultats plutôt que de se fier à une impression. Les garde-fous font passer la détection des urgences critiques de 4 sur 6 avec l'IA seule à 6 sur 6, et le routage vers le bon atelier atteint 97,5 %.

Pour les brouillons de réponse, le passage de Qwen 3B à 7B avec un prompt amélioré a fait monter les contrôles automatiques de 22 % à 82 %. Mais la relecture humaine a montré qu'une métrique automatique peut être trop optimiste : une métrique doit toujours être confrontée à une lecture humaine.

Compétences développées

  • Développement d'une API avec Python, FastAPI et Pydantic
  • Intégration d'un LLM local : sortie JSON structurée, délais maximum, nouvelles tentatives
  • Conception d'une architecture indépendante du modèle (interface AIProvider, faux fournisseur pour les tests)
  • Prompt engineering, garde-fous et sécurité face à l'injection de prompt
  • Évaluation d'un système d'IA sur un jeu de données annoté
  • Base de données avec SQLAlchemy et migrations Alembic
  • Tests automatisés avec pytest, outillage uv et ruff
